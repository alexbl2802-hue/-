# CARDINAL 2.0 — стартовые модули Godot 4.x

Это исходный набор модулей, не интегрированный в APK. Требуется Godot-проект.

## Подключение
1. Скопируйте `addons/cardinal/` в проект Godot.
2. Создайте Node `Cardinal` и прикрепите `cardinal_core.gd`; добавьте его в Autoload (Project Settings → Globals).
3. Добавьте `error_guardian.gd` и `performance_manager.gd` отдельными дочерними Node в игровую сцену; укажите ссылки `core` и `monitored_player` в инспекторе.
4. Добавьте CanvasLayer с `admin_panel.gd` в сцену и назначьте `core`. Включайте `developer_build` только для локальной тестовой сборки; НЕ включайте его в публичной сборке.
5. Для выдачи предметов вызывайте `CardinalItemSystem.roll_item({"damage":100}, CardinalItemSystem.Rarity.LEGENDARY)` и сохраняйте возвращённый словарь в данных предмета.
6. Интегрируйте события спавна и смерти монстров с `register_spawn()` / `register_despawn()`, а множители — с существующей логикой игры.

## Ограничения
- Это базовая реализация, а не готовая интеграция с игрой.
- World Director представлен управлением лимитом монстров и множителями; генератор событий, боссов, сундуков и таблиц добычи требуют подключения игровых сцен и данных.
- Error Guardian восстанавливает некорректную позицию игрока; он не исправляет произвольные ошибки исходного кода.
- Performance Manager регулирует только лимит монстров и требует профилирования на устройствах.
- Админ-панель доступна только в разработческой сборке; для выпуска отключите developer_build и удалите инструменты разработчика из релизного экспорта.

## Обновление CARDINAL 2.1 — Animation Guardian

Новый скрипт: `addons/cardinal/animation_guardian.gd`.

1. Добавьте обычный `Node` в тестовую сцену, прикрепите `animation_guardian.gd`.
2. В `player_paths` добавьте пути к `AnimationPlayer` персонажей (например, `../Hero/AnimationPlayer`).
3. Включите `scan_on_ready`, либо вызовите `scan_configured_players()` из своего отладочного меню.
4. Укажите `required_animation_names` (например, `Idle`, `Run`, `Attack`) согласно именам клипов вашего проекта.
5. Результаты доступны в `reports` и через сигнал `issue_found`. Для JSON-отчёта вызовите `export_report_json()`; файл сохраняется в `user://`.
6. По умолчанию `allow_safe_fixes = false`. При включении модуль может только задать стандартное время смешивания переходов, если оно равно нулю. Все остальные обнаруженные проблемы выводятся как рекомендации.

**Ограничения:** модуль не генерирует новые ключевые кадры, не исправляет геометрию, не ретаргетит скелеты и не гарантирует улучшение визуального качества. Исправление клипов и проблем рига выполняется в Blender/исходных GLB с повторным импортом в Godot. Проверка пути дорожки не гарантирует корректность bone/subproperty binding; это отдельный этап валидации. Сканирование запускайте в режиме диагностики, а не каждый кадр. Для публичной сборки отключите автосканирование и административные инструменты.
