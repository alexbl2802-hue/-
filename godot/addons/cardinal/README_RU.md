# CARDINAL AI 1.0 — Земли приключений

Набор исходных GDScript-модулей для Godot 4.x (ориентир: 4.7, Android). Это **новая пересборка**, не извлечённая из APK и не проверенная внутри вашего проекта.

## Установка
1. Скопируйте папку `addons/cardinal/scripts` в корень проекта Godot.
2. Project → Project Settings → Globals / Autoload: добавьте `res://addons/cardinal/scripts/cardinal.gd` под именем **Cardinal**.
3. На игровой уровень добавьте Node3D со скриптом `spawn_director.gd`, назначьте PackedScene монстров в Inspector.
4. В сцену монстра добавьте дочерний Node со скриптом `mob_component.gd`. Укажите `mob_id` (wolf, skeleton, spider или tower_guardian) и `is_boss`.
5. В сцену сундука добавьте дочерний Node со скриптом `chest_component.gd`. Вызывайте `open_chest()` при взаимодействии.
6. На отдельный Node добавьте `cardinal_guardian.gd` для диагностики.
7. Подключите сигналы `died`, `opened` к вашей системе инвентаря: сами предметы автоматически в инвентарь не добавляются.

## Функции
- Централизованный учёт всех зарегистрированных монстров и боссов, лимиты появления.
- Настраиваемый спавн любых сцен монстров; боссы запускаются отдельным вызовом `spawn_boss()`.
- Таблицы добычи для монстров, боссов и сундуков; вероятность, вес, количество.
- Адаптивная сложность через `Cardinal.set_player_performance(deaths, wins)`.
- Guardian: обнаружение некорректных значений, восстановление лимита и сложности, очистка недействительных ссылок.

## Важно
Guardian **не может автоматически переписать произвольный ошибочный GDScript**. Он устраняет только предусмотренные сбои во время выполнения и сообщает о прочих проблемах. Для анализа и исправления исходников нужен проект Godot, а не только APK.

Пример выдачи предметов: `var drops = $CardinalMobComponent.take_damage(10.0)` НЕ возвращает добычу; подпишитесь на сигнал `died(items)` и обработайте каждый словарь `{id, amount}`.

Для мобильной производительности снижайте `max_active_mobs` и используйте пулы объектов, если понадобится много врагов.
